## Правила

- Допустимые типы: `DECISION`, `ASSUMPTION`, `OPEN`, `SUPERSEDED`.

- Старые записи не удаляются: при замене им присваивается `SUPERSEDED`.

- Окончательные API-поля, HTTP-коды и технологический стек здесь не фиксируются.

## Анализ вариантов демонстрационного `pending`

| Вариант | Понятность | Влияние на UX | Риск смешения с production | Gherkin | Клиентская реализация |
|---|---|---|---|---|---|
| Специальная сумма | средняя | скрытое правило | высокий | просто, но семантически ложно | очень простая |
| Явный demo-переключатель | высокая | элемент только demo-mode | низкий | прозрачно | простая |
| Правило по ключу/счётчику | низкая для демонстратора | UI не меняется | средний | воспроизводимо, но неочевидно | средняя |

## Отклонённые варианты

| Тема | Отклонённый вариант | Причина |
|---|---|---|
| Граница модуля | Заканчивать после регистрации заявки | Не даёт согласованный результат обмена |
| Ввод суммы | Редактировать исходную и целевую сумму | Усложняет первую версию |
| Минимум | 1 единица любой исходной валюты | Не даёт единого экономического минимума |
| Изменение курса | Сравнивать полное значение API | Создаёт подтверждения из-за невидимых знаков |
| История | Память вкладки | Теряет записи после перезагрузки |
| История | Полноценный backend/БД | Расширяет demo-scope |
| Уведомления | Отдельная система для `pending` | Исключена пользователем |
| Отмена | `cancelled` и пользовательская отмена | Вне scope |
| Курс | Таймер истечения | Пользователь отказался |
| Demo pending | Специальная сумма | Выглядит как реальное финансовое правило |
| Demo pending | Скрытое правило ключа | Непонятно демонстратору и UX/Gherkin |
