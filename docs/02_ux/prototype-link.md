1. публикацию HTML/CSS/JavaScript через GitHub Pages;

3. ожидание успешной загрузки курса CoinGecko;
4. обычный обмен и окно «Обмен выполнен»;
5. раскрытие истории и пользовательский статус «Выполнена»;
6. открытие demo-настроек;
7. проверку мобильной ширины 390 px и отсутствия горизонтального переполнения.

Автоматический сценарий расположен в [`scripts/pages-smoke.mjs`](../../scripts/pages-smoke.mjs).

## Поддержанные сценарии

- RUB → USDT и USDT → RUB;
- целочисленный ввод, минимум и доступный баланс;
- автоматический расчёт с одним знаком после точки;
- повторная проверка курса и баланса перед созданием заявки;
- обычное подтверждение и отдельное согласие с изменившимся результатом;
- sync `completed`;
- `pending` с резервом;
- `pending → completed` и `pending → rejected`;
- безопасные ошибки курса и техническая ошибка;
- идемпотентный повтор operation key;
- локальное сохранение истории и demo-state;
- desktop и mobile.

## Локальный резервный запуск

Основным способом передачи является публичная ссылка. Для разработки из корня репозитория можно выполнить:

```bash
python -m http.server 8000
```

и открыть `http://localhost:8000/prototype/`.

## Ограничения

- Реальным внешним источником является только CoinGecko Simple Price API.
- Балансы, заявки, резерв, статусы и история являются клиентской demo-симуляцией.
- `localStorage` относится только к текущему браузеру и устройству.
- Demo-настройки не являются production-правилами.
- Утверждённый SDD и бизнес-логика не изменены.

## Скриншоты

WebP-файлы, созданные для первой реализации, сохранены в репозитории как исторический архив. Они не представляют финальный принятый интерфейс и не используются как актуальный формат передачи. Актуальным результатом является интерактивная публичная страница по ссылке выше.
