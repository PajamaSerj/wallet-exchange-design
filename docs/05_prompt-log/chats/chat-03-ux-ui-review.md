# CHAT-03 UX/UI — Manual Review Iteration

**Дата:** 2026-08-05  
**Статус:** AWAITING MANUAL SMOKE  
**Связанный этап:** CHAT-03 UX/UI

## Причина повторной итерации

Пользователь вручную проверил первоначальный прототип и подтвердил корректность бизнес-логики, но не принял этап из-за перегруженного экрана и удалённости основного действия. Было согласовано упростить UX/UI без изменения валютных пар, валидаций, подтверждений, changed-result, резерва, pending-сценариев, идемпотентности и локальной истории.

## Согласованная структура

- компактные непустые кошельки над формой;
- форма — главный элемент первого экрана;
- два соседних блока «Вы отдаёте» и «Вы получите»;
- центральная кнопка смены направления;
- одна основная кнопка «Обмен»;
- компактная строка курса, дата обновления в tooltip;
- demo-настройки под шестерёнкой;
- раскрывающаяся история ниже формы;
- mobile-компоновка в один столбец.

## Реализованные изменения

- удалены отдельный выбор «Направление обмена», кнопка «Проверить условия» и сообщение «Курс загружен»;
- ID котировки удалён с основного экрана и оставлен в истории;
- кошельки показывают только фактическую сумму и валюту; резерв появляется только при наличии;
- нулевые и скрытые кошельки не отображаются;
- добавлено удержание кнопки возле кошелька для временного показа приблизительного эквивалента; предусмотрены pointer-события, клавиатура и tooltip для hover/focus/long press;
- рассчитанная сумма показывается только после корректного ввода;
- demo-настройки дополнены пополнением, уменьшением и видимостью кошельков;
- пустой кошелёк нельзя включить до пополнения;
- история преобразована в компактный `details`-блок;
- сохранена миграция существующего `localStorage` из модели версии 3 в версию 4.

## Проверки текущей итерации

- `node --check` для `core.js`, `form.js`, `operations.js`, `app.js`;
- HTML разобран стандартным parser без дублирующихся ID;
- все DOM ID из `cacheDom()` присутствуют в HTML;
- изолированно проверены миграция `localStorage`, обе формулы, sync-операция, идемпотентный повтор и создание pending-резерва;
- восемь существующих WebP-скриншотов проверены побайтно и не изменены.

## Ограничения

- Playwright, Chromium и другая браузерная автоматизация не запускались;
- новые скриншоты не создавались;
- UX-spec, acceptance checklist, traceability, prototype README и screenshot index намеренно не синхронизированы до подтверждения успешного ручного smoke-теста;
- этап не считается завершённым.
