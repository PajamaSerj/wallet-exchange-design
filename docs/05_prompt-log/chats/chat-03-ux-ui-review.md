# CHAT-03 UX/UI — Manual Review and Acceptance

**Дата:** 2026-08-05  
**Статус:** ACCEPTED  
**Связанный этап:** CHAT-03 UX/UI

## Хронология

### 1. Первая ручная проверка

Пользователь вручную проверил первоначальный прототип. Бизнес-логика была оценена положительно, но этап не был принят из-за перегруженности экрана и удалённости основного действия.

Пользователь сформулировал требования к переработке:

- сделать форму главным элементом;
- разместить «Вы отдаёте» и «Вы получите» рядом со swap-кнопкой;
- заменить «Проверить условия» на «Обмен»;
- сократить отображение курса и кошельков;
- убрать общий блок эквивалента;
- добавить hold-to-preview возле каждого кошелька;
- перенести demo-сценарии под шестерёнку;
- сделать историю компактной и раскрывающейся;
- сохранить всю бизнес-логику, резерв, оба направления, идемпотентность и `localStorage`.

До реализации была предложена структура нового экрана, которую пользователь подтвердил.

### 2. Первая доработка

Были реализованы единая главная форма, компактные кошельки, settings drawer, hold-to-preview, скрытый до ввода target и раскрывающаяся история. Бизнес-правила не изменялись.

По прямому указанию пользователя:

- screenshots не создавались и не обновлялись;
- Playwright/Chromium не запускались;
- выполнялись только статические, DOM- и изолированные lifecycle-проверки.

### 3. Повторная ручная проверка

Пользователь сообщил, что новый вариант выглядит значительно лучше, и сформулировал финальные замечания:

- убрать дублирующие подписи в карточке;
- перенести кошельки внутрь основной карточки;
- удалить секцию «Последняя заявка»;
- использовать короткий outcome dialog;
- оставить подробности только в истории;
- показывать русские пользовательские статусы вместо внутренних английских значений.

### 4. Финальная доработка

В результате:

- кошельки размещены над формой внутри основной карточки;
- отдельная секция результата удалена;
- после операции показывается короткий dialog со статусом, сообщением и кнопкой «Ок»;
- в history UI применены «Заявка создана», «В обработке», «Выполнена», «Отклонена»;
- суммы, направление, курс, дата, request ID и quote ID доступны только в раскрытой истории;
- demo-завершение pending находится в деталях pending-заявки;
- сохранены обе пары, валидации, confirmations, changed-result, reserve lifecycle, async terminal-исходы, идемпотентность, demo-настройки и локальное хранение.

### 5. Финальная приёмка

После повторной ручной проверки пользователь явно подтвердил:

> «Я завершил ручную проверку и принимаю текущий интерфейс как финальный вариант UX/UI-прототипа.»

CHAT-03 принят по UX/UI. Проектный статус `VERIFIED` не устанавливается, поскольку Gherkin, OpenAPI, межартефактная интеграция и независимый итоговый аудит относятся к будущим этапам.

## Скриншоты

Восемь WebP-файлов первой реализации сохранены без изменений как исторический архив. Они не являются актуальным представлением принятого интерфейса. Основной формат передачи — публичный интерактивный прототип:

[https://pajamaserj.github.io/wallet-exchange-design/](https://pajamaserj.github.io/wallet-exchange-design/)

## Проверки до публикации

- `node --check` для четырёх JavaScript-модулей;
- HTML parsing, уникальные ID и наличие DOM-контрактов;
- обе формулы, validation boundaries, sync/pending/rejected, reserve и idempotency;
- миграция `localStorage`;
- repository quality gates;
- mergeability PR.

## Проверка после публикации

Workflow `.github/workflows/pages.yml` должен подтвердить HTML/CSS/JavaScript, загрузку курса, обычный обмен, outcome dialog, настройки, историю и mobile 390 px. Факт успешной публикации фиксируется отдельно после deploy из `main`.
