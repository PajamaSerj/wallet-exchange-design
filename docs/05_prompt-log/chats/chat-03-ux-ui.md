## Принятые UX-решения

| Решение | Реализация | Классификация |
|---|---|---|
| Деловая двухколоночная композиция desktop | form + визуально отдельная demo-панель, история ниже | самостоятельная UX-интерпретация |
| Mobile перестраивается в один столбец | те же данные и бизнес-действия, карточная история | реализация `UX-003` |
| Один однозначный курс | всегда `1 USDT = X RUB`, независимо от пары | реализация SDD |
| Минимум RUB | `ceil(rate)` RUB для результата не ниже `1.0 USDT` | реализация бизнес-правила |
| Изменение результата | сравнение только округлённых target amounts | реализация `DEC-012`/SDD |
| Demo-async | явный переключатель, отдельный terminal selector | реализация `DEC-036` |
| Demo actual rate | контролируемое отличие от подтверждённого курса | демонстрация, не production-правило |
| История | локальные карточки с требуемыми бизнес-полями | реализация `DEC-027` |
| Системный шрифт | `Inter`-подобный system stack без загрузки font-файлов | самостоятельная интерпретация |
| Токены | пурпурно-малиновый акцент, нейтральные поверхности, радиусы 12–18 px | самостоятельная интерпретация, не токены Bidzaar |

## Ошибки, галлюцинации и неточные предложения ИИ

| Проблема / риск | Как обнаружено | Исправление |
|---|---|---|
| Скрытый триггер `pending` мог выглядеть как бизнес-правило | сверка с `DEC-036` и SDD §15 | оставлен только явный demo-переключатель в отделённой панели |
| Возможное сравнение полного значения курса | сверка с `DEC-012`/`BRL-008` | сравниваются отображаемые результаты после округления |
| Риск показать второе обычное окно после согласия с новым результатом | проверка пользовательского потока | changed-result согласие сразу вызывает обработку |
| Риск уменьшить общий баланс уже в `pending` | сверка с SDD §11–12 и диаграммой async | в `pending` меняется только `reserved`/`available`; total списывается при `completed` |
| Риск оставить резерв у terminal-заявки | проверка инварианта active reserve only pending | async completion списывает резерв; rejection освобождает его |
| Риск повторно применить результат | сценарий повторной обработки ключа | `processedKeys` возвращает сохранённую заявку без нового финансового эффекта |
| Риск превратить demo-фактический курс в production-логику | UX-ревью demo-панели и текстов | механизм явно маркирован «только демонстрация» |
| Риск буквального копирования Bidzaar | сравнение с `DEC-033`–`DEC-034` | не использованы логотип, тексты, структура или закрытые токены; создана самостоятельная система |
| Риск недоступного switch/select | keyboard и label-проверка | нативные inputs, связанные `label`, focus ring и настоящий `disabled` |
| Локальная навигация браузера была заблокирована политикой среды | ошибка Chromium при переходе на localhost/file URL | сценарии выполнялись через инъекцию фактических HTML/CSS/JS; CoinGecko перехватывался детерминированным ответом |

## Ручные исправления

- Удалено любое поведение, которое могло бы выглядеть как скрытое production-условие `pending`.
- Статусы ограничены `created`, `pending`, `completed`, `rejected`; `cancelled` и `expired` не введены.
- Формулы и округление сверены для обеих пар.
- «Обменять всё» переведено на доступный, а не общий остаток.
- Pending-резерв отделён от списания total.
- Подтверждённые и фактические async-значения показываются отдельно.
- Demo-контролы визуально и текстово отделены от продукта.
- В элементах управления сохранены нативная семантика, keyboard access и focus-visible.

## Ручной UX-review и переработка интерфейса — 2026-08-05

### Обратная связь пользователя

Пользователь подтвердил корректность бизнес-логики, но не принял этап из-за перегруженного экрана и удалённости основного действия. Было согласовано упростить интерфейс без изменения валютных пар, валидаций, подтверждений, changed-result, резерва, pending-сценариев, идемпотентности и локальной истории.

### Внесённые изменения

- форма обмена стала главным элементом первого desktop-экрана;
- исходная и целевая валюты представлены соседними блоками с центральной кнопкой смены направления;
- основная кнопка переименована в «Обмен», техническая кнопка «Проверить условия» и сообщение «Курс загружен» удалены;
- курс сокращён до одной справочной строки, время обновления перенесено в tooltip, ID котировки оставлен только в истории;
- кошельки сокращены до фактической суммы и валюты, резерв показывается только при наличии;
- нулевые и скрытые кошельки не отображаются на основном экране;
- вместо общего эквивалента добавлено удержание кнопки возле каждого кошелька для временного показа приблизительной конвертации; предусмотрены pointer-события, клавиатура и tooltip для hover/focus/long press;
- получаемая сумма показывается только после корректного ввода;
- demo-настройки перенесены под шестерёнку и дополнены пополнением/уменьшением балансов и управлением видимостью кошельков;
- пустой кошелёк нельзя включить до пополнения;
- история преобразована в компактный раскрывающийся блок;
- сохранена миграция состояния `localStorage` версии 3 в обновлённую модель версии 4.
