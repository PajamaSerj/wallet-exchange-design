# UX/UI Prototype

**Chat ID:** CHAT-03  
**Этап:** UX/UI и frontend-прототип  
**Статус:** COMPLETED — MANUALLY ACCEPTED / PUBLICATION CHECK PENDING  
**Дата:** 2026-08-05

## Цель

Создать концептуальный интерактивный статический прототип обмена RUB/USDT, реализующий утверждённый SDD от открытия формы до `completed` или `rejected`, подготовить UX-спецификацию и governance-доказательства, провести пользовательскую UX-приёмку и опубликовать прототип по открытой ссылке без запуска следующих этапов.

## Исходная реализация

Первая версия включала:

- обычные HTML/CSS/JavaScript без сборщика;
- обе валютные пары и CoinGecko;
- валидации, normal/changed-result confirmation;
- sync `completed`;
- воспроизводимые `pending → completed/rejected`;
- резерв, идемпотентность и `localStorage`;
- отдельные блоки кошельков, формы, demo-панели, результата и истории;
- восемь WebP-снимков состояний;
- первичные UX-spec, acceptance, traceability и инструкции.

Первая реализация прошла синтаксические, изолированные бизнес-проверки и браузерные сценарии. Бизнес-логика была признана корректной, но UX/UI не был принят как финальный.

## Ручной UX-review пользователя

После просмотра первой реализации пользователь:

1. подтвердил, что логика выглядит хорошо;
2. не принял этап из-за перегруженности экрана и удалённости основного действия;
3. потребовал сделать форму главным объектом, объединить валютные панели, сократить курс и кошельки, перенести demo-настройки под шестерёнку и свернуть историю;
4. отдельно запретил обновлять screenshots и запускать браузерную автоматизацию до ручной проверки интерфейса.

Согласованная структура была описана до реализации и подтверждена пользователем.

## Первая UX-доработка

Без изменения бизнес-логики были выполнены:

- форма стала главным объектом desktop/mobile;
- «Вы отдаёте» и «Вы получите» оформлены соседними панелями со swap-кнопкой;
- основная кнопка переименована в «Обмен»;
- технические «Проверить условия» и «Курс загружен» удалены;
- курс сокращён до одной строки, время перенесено в tooltip, quote ID оставлен в истории;
- кошельки сокращены до фактической суммы и валюты;
- резерв отображается только при наличии;
- нулевые/скрытые кошельки не показываются;
- добавлено удержание `≈` для временной приблизительной конвертации pointer/touch/keyboard;
- target скрывается до корректного ввода;
- demo-настройки перенесены в settings drawer и дополнены управлением балансами и видимостью;
- история стала раскрывающимся блоком;
- добавлена миграция `localStorage` v3 → v4.

Для этой итерации выполнялись только `node --check`, HTML/DOM-контракты и изолированные lifecycle-тесты. Screenshots остались побайтно неизменными.

## Финальные UX-замечания пользователя

После повторного просмотра пользователь отметил значительное улучшение и запросил финальный раунд:

- убрать дублирующие подписи внутри карточки;
- перенести кошельки внутрь основной карточки над формой;
- удалить отдельную секцию «Последняя заявка»;
- заменить её коротким outcome dialog со статусом, сообщением и кнопкой «Ок»;
- показывать в UI русские бизнес-статусы вместо внутренних английских значений;
- оставить полные детали только в истории.

## Финальная реализация

В итоговой версии:

- кошельки находятся внутри карточки обмена;
- отдельные заголовки направления/карточки и секция «Последняя заявка» отсутствуют;
- обычный результат, pending, rejection и безопасные ошибки показываются коротким dialog;
- outcome dialog не повторяет ID, курс и подробные суммы;
- история является единственным местом полных деталей заявки;
- статусы отображаются как «Заявка создана», «В обработке», «Выполнена», «Отклонена»;
- demo-завершение pending находится в раскрытой pending-заявке;
- обе пары, формулы, проверки, changed-result, резерв, async terminal-исходы, идемпотентность, demo-настройки и локальное хранение сохранены.

## Ключевые UX-решения

| Решение | Финальная реализация | Классификация |
|---|---|---|
| Форма — главный объект | единая карточка с кошельками, source/target, action и rate | самостоятельная UX-композиция |
| Направление | центральная swap-кнопка вместо отдельного блока выбора | реализация двух разрешённых пар |
| Кошельки | только непустые видимые; reserve по наличию; hold-to-preview | реализация требований пользователя |
| Курс | одна строка; updated time в tooltip; quote ID только в истории | UX-упрощение без изменения quote logic |
| Outcome | короткий dialog без технических деталей | пользовательская финальная правка |
| Статусы | русские бизнес-формулировки; внутренние значения сохранены в данных | разделение UI и модели/API |
| История | единственное место полных деталей и pending finalize | реализация `DEC-027` |
| Demo controls | отдельный settings drawer | реализация `DEC-036`, не production |
| Mobile | один столбец без горизонтального overflow | реализация `UX-003` |

## Ошибки, риски и исправления ИИ

| Риск | Обнаружение | Исправление |
|---|---|---|
| Скрытый trigger `pending` выглядел бы бизнес-правилом | сверка с `DEC-036` | только явный demo-switch |
| Сравнение полного курса вместо отображаемого результата | сверка с SDD | сравнение target после округления |
| Второе normal confirmation после changed-result | flow review | согласие сразу создаёт заявку |
| Списание total в `pending` | сверка с reserve lifecycle | меняется reserved/available, total списывается при completed |
| Резерв у terminal status | проверка инварианта | completion списывает, rejection освобождает |
| Повторный финансовый эффект | idempotency test | `processedKeys` возвращает существующую заявку |
| Demo actual rate мог выглядеть production-правилом | UX-review | явная demo-маркировка |
| Буквальное копирование Bidzaar | governance review | самостоятельные токены и структура |
| Перегруженная первая композиция | ручной review пользователя | форма стала главным объектом, технические блоки скрыты/удалены |
| Дублирование результата | финальный review пользователя | outcome dialog + история как единственный источник деталей |
| Английские статусы в UI | финальный review пользователя | business status mapping на русский |
