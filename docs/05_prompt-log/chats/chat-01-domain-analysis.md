## Подтверждённый scope

В scope входят:

- выбор RUB → USDT или USDT → RUB;
- получение и отображение котировки;
- ввод исходной суммы и автоматический расчёт получаемой;
- проверка доступного баланса;
- повторная проверка курса и баланса перед созданием заявки;
- подтверждение неизменившегося или обновлённого результата;
- создание одной заявки на одну пользовательскую попытку;
- синхронное завершение или переход на дополнительную проверку;
- резервирование для `pending`;
- доведение заявки до `completed` или `rejected`;
- отображение результата и локальной истории заявок обмена;
- согласованные ошибки и исключительные состояния.

## Явный out of scope

Регистрация и авторизация; KYC/AML; пополнение и вывод; карты; переводы; глобальная история финансовых операций; административная панель; биржевая инфраструктура; собственный сервис рыночных данных; бухгалтерский или блокчейн-реестр; система уведомлений; поддержка; лояльность; пользовательская отмена; комиссии и спред; production-архитектура и технологический стек.

## Предварительный глоссарий

| Термин | Предварительное определение |
|---|---|
| Заявка на обмен | Бизнес-объект, фиксирующий намерение обменять исходную сумму на целевую и живущий от создания до `completed` или `rejected`. |
| Обмен | Изменение двух валютных балансов по фактическому курсу выполнения. |
| Исходная валюта | Валюта, средства которой пользователь отдаёт. |
| Целевая валюта | Валюта, средства которой пользователь получает. |
| Валютная пара | Разрешённое направление RUB → USDT или USDT → RUB. |
| Исходная сумма | Положительное целое количество исходной валюты, введённое пользователем. |
| Получаемая сумма | Рассчитанное количество целевой валюты; отображается с округлением до одного знака после точки. |
| Курс | Цена 1 USDT в RUB, полученная из согласованного источника и используемая в формуле направления. |
| Актуальный курс | Повторно полученный курс непосредственно перед созданием заявки. |
| Котировка | Идентифицированный снимок курса и времени обновления источника. |
| Баланс | Общее количество конкретной валюты в демонстрационном кошельке. |
| Доступный баланс | Общий баланс за вычетом активных резервов. |
| Подтверждение | Явное согласие пользователя с исходной и отображаемой получаемой суммами. |
| Изменение курса | Изменение отображаемой получаемой суммы после повторного расчёта и округления. |
| Срок действия курса | Для пользователя не показывается; исходная котировка применяется для предварительного расчёта до отправки, затем обязательна повторная проверка. |
| Статус заявки | Одно из значений `created`, `pending`, `completed`, `rejected`; последние два терминальные. |
| Резерв | Часть исходного баланса, временно исключённая из доступного остатка для заявки `pending`. |
| Ключ операции | Идентификатор одной пользовательской попытки подтверждения, используемый для предотвращения дублей. |
| Локальная история | Представление заявок обмена, сохранённое в `localStorage` текущего браузера. |

## Предварительная модель предметной области

Модель является материалом анализа, а не схемой БД или окончательной API-моделью.

| Сущность | Назначение | Ключевые бизнес-атрибуты |
|---|---|---|
| Кошелёк пользователя | Контекст владения балансами демонстрационного пользователя | идентификатор пользователя/кошелька, набор валютных балансов |
| Валютный баланс | Состояние средств одной валюты | валюта, общий остаток, резерв, доступный остаток |
| Котировка | Условия предварительного расчёта | ID котировки, валютная пара, курс, время обновления источника, время получения |
| Заявка на обмен | Жизненный цикл обмена | ID, кошелёк, валюты, исходная сумма, предварительная получаемая сумма, подтверждённая котировка, статус, времена, резерв, фактические значения при завершении |
| Резерв | Блокировка исходных средств для `pending` | ссылка на заявку, валюта, сумма, признак активности/освобождения/списания как бизнес-смысл |
| Пользовательская попытка | Граница идемпотентности | ключ операции, связанная заявка, результат первой обработки |
| Запись истории | Данные для локального просмотра | ID заявки, направление, суммы, статус, времена, предварительные и фактические значения при наличии |

### Связи

- один кошелёк содержит по одному рассматриваемому балансу RUB и USDT;
- одна заявка относится к одному кошельку и одной подтверждённой котировке;
- одна пользовательская попытка создаёт не более одной заявки;
- заявка `pending` имеет один активный резерв исходной валюты;
- запись истории является пользовательским представлением заявки, а не отдельной финансовой операцией.

### Жизненный цикл

- синхронный: `created → completed` или `created → rejected`;
- асинхронный: `created → pending → completed` или `created → pending → rejected`;
- `pending` создаёт резерв;
- `completed` применяет обмен и закрывает резерв списанием;
- `rejected` освобождает резерв;
- `completed` и `rejected` терминальны;
- `cancelled` и `expired` не используются.

### Возможные события

`form_opened`, `quote_received`, `amount_changed`, `submission_started`, `quote_rechecked`, `result_changed`, `user_confirmed`, `request_created`, `funds_reserved`, `request_pending`, `exchange_completed`, `request_rejected`, `reserve_released`, `history_updated`.

Названия событий предварительны и не являются именами API или технических сообщений.

## Минимальные контракты внешних зависимостей

| Зависимость | Что передаётся/получается | Минимально необходимое поведение |
|---|---|---|
| CoinGecko Simple Price | Запрос цены `tether` в `rub`; ответ с положительной ценой и `last_updated_at` | Вернуть корректную котировку либо ошибку недоступности/неполного ответа |
| Источник баланса | Запрос общих и зарезервированных остатков RUB/USDT | Вернуть данные для вычисления доступного баланса и повторной проверки |
| Дополнительная проверка | Заявка и подтверждённые условия | Вернуть `pending`, затем `completed` или `rejected`; внутренняя реализация вне scope |
| `localStorage` | Минимальные записи истории и демонстрационные балансы | Сохранять данные в текущем браузере между перезагрузками |

## Основные бизнес-правила

- поддерживаются только RUB/USDT в обоих направлениях;
- пользователь вводит только исходную сумму;
- минимум равен эквиваленту 1.0 USDT, максимум — доступному балансу;
- исходный ввод целочисленный, отображаемый результат округляется до десятых;
- комиссия, спред и дополнительные лимиты отсутствуют;
- повторное согласие требуется только при изменении отображаемого результата;
- одна пользовательская попытка не может создать дубль заявки или повторно изменить баланс;
- `pending` резервирует средства;
- пользовательская отмена и отдельные уведомления отсутствуют;
- локальная история содержит только заявки этого модуля.

## Визуальный ориентир

Зафиксировано общее настроение Bidzaar, без буквального копирования: насыщенный пурпурно-малиновый акцент, нейтральные поверхности, контрастная гротескная типографика, компактная деловая плотность, тонкие разделители и умеренно прямоугольные контейнеры. Точные цвета, радиусы, тени, размеры и шрифт должны быть обозначены UX-чатом как проектная интерпретация.
