# Wallet Exchange Prototype

**Статус:** IMPLEMENTED / CHAT-03  
**Назначение:** концептуальный интерактивный UX/UI-прототип создания и доведения заявки RUB/USDT до `completed` или `rejected`.

Прототип реализован на обычных HTML, CSS и JavaScript без сборщика, серверной части и внешних UI-библиотек. Клиентский код разделён на `core.js` (состояние, хранение, котировки), `form.js` (расчёт, валидация, подтверждения), `operations.js` (баланс, резерв и статусы) и `app.js` (представление, история и события). Реальные внешние данные используются только для курса Tether в RUB; кошелёк, баланс, резерв, заявки, статусы, история и идемпотентные ключи симулируются в браузере.

## Локальный запуск

Из корня репозитория:

```bash
python -m http.server 8000
```

Открыть:

```text
http://localhost:8000/prototype/
```

Прямое открытие `prototype/index.html` также возможно, но локальный HTTP-сервер предпочтителен из-за сетевого запроса CoinGecko и одинакового поведения браузеров.

## CoinGecko

Используется endpoint:

```text
https://api.coingecko.com/api/v3/simple/price?ids=tether&vs_currencies=rub&include_last_updated_at=true
```

Проверяются положительная цена `tether.rub` и корректный `last_updated_at`. Запрос выполняется при открытии формы и повторно перед созданием заявки. Таймаут клиентского запроса — 8 секунд. При недоступности или некорректном ответе заявка не создаётся.

## Демонстрационные начальные балансы

| Валюта | Общий | Зарезервировано | Доступно |
|---|---:|---:|---:|
| RUB | 250 000.0 | 0.0 | 250 000.0 |
| USDT | 1 250.0 | 0.0 | 1 250.0 |

Это тестовые данные, а не финансовая информация реального пользователя.

## Сброс состояния

Нажать **«Сбросить демо-данные»** в шапке. Будут удалены тестовые балансы, резервы, история, обработанные ключи и настройки демонстрационных сценариев из `localStorage`.

Альтернативно удалить ключ `wallet-exchange-demo-v3` в DevTools → Application → Local Storage.

## Воспроизведение сценариев

### Синхронный успех

1. Оставить demo-переключатели выключенными.
2. Ввести допустимую целую сумму, например `10000` RUB.
3. Нажать **«Проверить условия»**.
4. Подтвердить обычное окно.
5. Заявка завершится `completed`, исходный баланс уменьшится, целевой увеличится.

### `pending → completed`

1. В demo-панели включить **«Дополнительная проверка»**.
2. Выбрать `pending → completed`.
3. Создать и подтвердить заявку.
4. Проверить резерв и уменьшившийся доступный баланс.
5. Нажать **«Завершить демо-проверку»** в результате.
6. Резерв будет списан, целевой баланс увеличится на фактическую сумму.

### `pending → rejected`

1. Включить **«Дополнительная проверка»**.
2. Выбрать `pending → rejected`.
3. Создать и подтвердить заявку.
4. Нажать **«Завершить демо-проверку»**.
5. Резерв освободится, целевая валюта не будет зачислена.

### Недостаточный баланс

Ввести сумму больше доступного остатка, например `999999` RUB. Поле покажет актуальный доступный баланс, а кнопка будет заблокирована настоящим атрибутом `disabled`.

### Изменение отображаемого результата

1. Включить demo-переключатель **«Изменить результат»**.
2. Ввести допустимую сумму и нажать **«Проверить условия»**.
3. Свежая котировка CoinGecko будет явно и только для демонстрации скорректирована на `+1.5%`.
4. Появится отдельное окно **«Результат изменился»** с прежним и новым итогом.
5. После согласия дополнительное обычное подтверждение не показывается.

### Ошибка CoinGecko

Включить **«Ошибка CoinGecko»** и отправить допустимую сумму. Следующий запрос завершится контролируемой demo-ошибкой; заявка и финансовый эффект не создаются. Переключатель автоматически выключится.

### Общая техническая ошибка

Включить **«Техническая ошибка»** и отправить допустимую сумму. Показывается безопасный пользовательский текст с кратким demo-кодом; заявка не создаётся.

### Идемпотентный повтор

После создания первой заявки нажать **«Повторить последний ключ»**. Прототип вернёт существующую заявку по сохранённому ключу без повторного списания, зачисления, резервирования или новой записи истории.

## Клиентская симуляция и production

- `localStorage` используется только для демонстрации и не является допустимым production-хранилищем финансовой истины.
- Demo-переключатели, выбор терминального async-результата, коррекция курса, искусственные ошибки и кнопка завершения проверки не являются production-правилами.
- Production-система должна выполнять повторную проверку и атомарные финансовые операции на доверенной стороне, сохранять идемпотентность и обрабатывать внешние события независимо от вкладки браузера.
- Прототип не моделирует авторизацию, KYC/AML, пополнение, вывод, карты, переводы, уведомления, поддержку, комиссию, спред, отмену, `cancelled` или `expired`.
