# Wallet Exchange Prototype

**Статус:** CHAT-03 COMPLETED / MANUALLY ACCEPTED  
**Публичная версия:** [https://pajamaserj.github.io/wallet-exchange-design/](https://pajamaserj.github.io/wallet-exchange-design/)

Концептуальный интерактивный UX/UI-прототип демонстрирует создание и доведение заявки RUB/USDT до `completed` или `rejected`. Итоговый интерфейс принят пользователем после ручного UX-review, двух раундов доработки и повторного smoke-теста.

## Реализация

Прототип работает на обычных HTML, CSS и JavaScript без сборщика, backend и внешней UI-библиотеки:

- `core.js` — состояние, миграция `localStorage`, котировки и форматирование;
- `form.js` — расчёт, валидация и подтверждения;
- `operations.js` — заявка, баланс, резерв, lifecycle и идемпотентность;
- `app.js` — представление, история, demo-настройки и события.

Реальным внешним источником является только курс Tether/RUB. Балансы, резервы, заявки и история симулируются в браузере.

## Финальная структура интерфейса

- компактные непустые кошельки находятся внутри основной карточки над формой;
- форма состоит из соседних блоков «Вы отдаёте» и «Вы получите» с центральной кнопкой смены направления;
- основное действие называется «Обмен»;
- результат расчёта появляется только после корректного ввода;
- курс показан компактной строкой, время обновления доступно в подсказке;
- ID котировки и ID заявки доступны только в раскрытых деталях истории;
- результат операции показывается коротким всплывающим окном;
- история является единственным местом с полными деталями заявки;
- пользовательские статусы: «Заявка создана», «В обработке», «Выполнена», «Отклонена»;
- demo-настройки находятся под шестерёнкой и включают управление балансами, видимостью кошельков, ошибками, изменением результата и async-сценариями.

## Основной способ запуска

Открыть публичную страницу:

[https://pajamaserj.github.io/wallet-exchange-design/](https://pajamaserj.github.io/wallet-exchange-design/)

Git, Python, локальный сервер и авторизация не требуются.

## Локальный резервный запуск

Из корня репозитория:

```bash
python -m http.server 8000
```

Открыть `http://localhost:8000/prototype/`.

## CoinGecko

Используется endpoint:

```text
https://api.coingecko.com/api/v3/simple/price?ids=tether&vs_currencies=rub&include_last_updated_at=true
```

Запрос выполняется при открытии формы и повторно перед подтверждением заявки. Проверяются положительная цена `tether.rub` и корректный `last_updated_at`. При ошибке или некорректном ответе заявка не создаётся.

## Сценарии ручной проверки

### Обычный обмен

1. Оставить demo-переключатели выключенными.
2. Ввести допустимую целую сумму.
3. Нажать **«Обмен»**.
4. Подтвердить условия.
5. Закрыть окно «Обмен выполнен» кнопкой **«Ок»**.
6. Раскрыть историю и проверить статус «Выполнена», суммы, направление, курс, дату и идентификаторы.

### `pending → completed` / `pending → rejected`

1. Открыть настройки шестерёнкой.
2. Включить «Дополнительная проверка» и выбрать terminal-исход.
3. Создать заявку.
4. Проверить окно «Заявка принята и передана на проверку» и резерв у кошелька.
5. В раскрытой pending-заявке нажать «Завершить демо-проверку».
6. Проверить статус «Выполнена» либо «Отклонена» и корректное списание или освобождение резерва.

### Изменение результата

Включить «Изменить результат», создать заявку и согласиться с новым отображаемым результатом. Второе обычное подтверждение после согласия не показывается.

### Ошибки и идемпотентность

- «Ошибка CoinGecko» и «Техническая ошибка» не создают заявку и показывают безопасный пользовательский текст.
- «Повторить последний ключ» возвращает существующую заявку без повторного финансового эффекта и без дублирования истории.

## Данные и сброс

Состояние сохраняется в `localStorage` с миграцией предыдущей версии demo-модели. Кнопка «Сбросить демо-данные» в настройках удаляет тестовые балансы, резервы, историю, обработанные ключи и demo-параметры.

## Ограничения

- `localStorage` не является production-хранилищем финансовой истины.
- Demo-переключатели и искусственное изменение балансов не являются бизнес-правилами продукта.
- Production-backend, авторизация, KYC/AML, пополнение/вывод, уведомления, комиссия, спред и пользовательская отмена не реализованы.
- Утверждённый SDD и бизнес-правила прототипом не изменяются.

## Проверка публикации

Workflow `.github/workflows/pages.yml` публикует каталог `prototype/` как корень GitHub Pages и после деплоя запускает `scripts/pages-smoke.mjs`. Smoke-проверка контролирует HTML/CSS/JavaScript, загрузку курса, обычный обмен, окно результата, настройки, историю и мобильную ширину.
